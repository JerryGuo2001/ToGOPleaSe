# Measurement and data format

## Decision lifecycle

Load → welcome/instructions → Start → fullscreen request settles → presenting → choosing → processing → presenting. After response 10: finalized. A genuine game FINISH/quit or infrastructure error finalizes early. Instruction navigation, Start, inventory pagination and Bag viewing are never commands. Bag reads the latest inventory snapshot; it does not send INVENTORY to the interpreter. There are no background LOOK/INVENTORY probes.

A decision is an accepted action whose command returns a response at the next original input boundary (including parser-recognized unsuccessful actions). Every successful command delivery consumes one experimental decision even when Zork's own moves counter is unchanged. The worker and controller reject overlapping requests; the controller closes the worker at finalization. Mouse click events with `detail > 1` are ignored; keyboard activation is supported.

Normal Zork death may resurrect the player. The adapter stops only at actual VM quit or the verified r119 FINISH management prompt, not on a generic “you have died” string. The test fixture reaches this routine by three actual deaths with no state patching.

## Timing

The game is preloaded but hidden while the participant reads the welcome and instruction pages. The final Start button requests fullscreen from its click handler. After that request resolves or rejects (or is skipped if unsupported), the controller starts the session and reveals the narrative and three large Move / Action / Bag buttons with disabled buttons. Every decision starts at this category menu; game choices are hidden until a category is selected. Each category independently retains at most nine choices, all displayed together below the story with a separate Back card. Back (or Escape when delivered to the page by the browser) returns to the category menu, restoring keyboard focus to the category just left. Empty categories still offer Back. Two `requestAnimationFrame` callbacks provide layout/render opportunities; when the document is visible, the controller samples both clocks and enables the buttons in the same task. Buttons cannot issue commands while waiting for that activation. The next actual paint is typically within one display frame, but JavaScript cannot observe the physical onset of a monitor pixel. Category visits and Back/Escape do not restart the timer or execute a command. Long inventories use page controls sized to the available viewport; only the story transcript scrolls. Choices never paginate.

`timestamp_presented`, `timestamp_clicked`, `timestamp_response` are ISO UTC timestamps. The first statement in the click handler samples `performance.now()` and `new Date().toISOString()`. `rt_ms` is the difference between monotonic click and presentation samples; wall-clock jumps do not enter that subtraction. Values are not rounded or corrected.

`processing_ms` runs from click until the main thread receives the completed command response/state/menu from the worker. It includes controller/recovery-write overhead, message transport, interpretation, state inspection and action generation. It is **not** included in RT and is not a pure VM CPU benchmark. Post-response rendering and the next two-frame activation wait are outside both that row's RT and processing duration.

`visibility_interrupted=true` if a visibility-hidden event occurs during choosing or processing. The flag is deliberately conservative: an interruption after the click still flags the step. RT values remain unchanged. An initially hidden page does not activate a timer; it waits until visible. This does not detect distraction, all forms of window occlusion, or loss of attention.

The first narrative and action buttons are hidden before Start. Instruction reading and the initial fullscreen transition are outside RT. RT includes narrative/history reading, category browsing, Bag viewing and inventory pagination; these do not restart the timer. Category and inventory page visits are recorded in session JSON `ui_events` with timestamps and the upcoming step number. RT1 is postactivation choice latency after the game is revealed, subject to the paint-onset limitation above. Fullscreen may be unavailable or declined, in which case the same game fills the browser viewport; successful fullscreen is not required and is not recorded as a separate experimental condition. Trial timing on different refresh rates/devices/assistive technologies is not claimed to be equivalent. Avoid interpreting sub-frame differences as precise physical stimulus timing.

## CSV schema

`js/data_save.js` defines the authoritative fixed column order, beginning with all 21 requested columns:

`participant_id`, `step`, `game_version`, `game_location_before`, `game_location_after`, `available_actions`, `selected_action_id`, `selected_action_label`, `command_sent`, `game_text_before`, `game_text_after`, `inventory_before`, `inventory_after`, `score_after`, `timestamp_presented`, `timestamp_clicked`, `timestamp_response`, `rt_ms`, `processing_ms`, `visibility_interrupted`, `session_status`.

Additional columns are `experiment_version`, `action_generator_version`, `story_sha256`, `interpreter_version`, `random_seed`, `termination_reason`, `location_id_before`, `location_id_after`, `moves_before`, `moves_after`, `performance_presented_ms`, `performance_clicked_ms`, `performance_response_ms`, `time_origin_ms`, `game_raw_text_after`, `command_outcome`, `story_id`, `menu_category`.

- Each row is one confirmed processed command. Steps are contiguous from 1.
- `available_actions` contains the retained choices in Move, Action, Bag order, with at most nine per category, including `{id,label,command,category,menuGroup,menuPriority}` and optional story metadata. This exact array is authorized by the worker and captured before the click. It excludes pruned choices and does not imply every category was viewed. `menu_category` is `move`, `action` or `bag`. JSON `ui_events` records category selections, returns through Back/Escape as `categories`, and inventory page visits. Moving keyboard focus among category buttons does not open them or create an event; Enter or Space selects the focused button. Automatic return to the category menu on a new turn is not a visit. Back is not a game choice and never appears in `available_actions`.
- Inventory cells are arrays of accessible carried object `{id,symbol,name,parent}` entries. Sealed contents are not guessed. Room IDs disambiguate multiple rooms named Forest, Maze, etc.
- For Zork, score and move counters come directly from signed score/unsigned moves globals. JSON stories update these from authored score effects and executed choices.
- `game_text_before` is the latest individual game response, retained unchanged while viewing inventory or switching categories. The visible story history also contains the opening text and prior choices/responses; it is not concatenated into this CSV cell. Reconstruct the transcript from `initial_narrative` in session JSON and each CSV row’s `selected_action_label` / `game_text_after`. `game_text_after` is exactly the command response shown next. Narrative whitespace and quotes are retained; only the terminal `>` input cursor is excluded. `game_raw_text_after` retains the complete main-window output. No command echo is injected. Status-window layout and UI headings are separate.
- Finalization updates every row's `session_status` to `completed` or `early_termination`. `termination_reason` is `decision_limit`, `story_finish`, `vm_quit`, `initialization_error`, `interpreter_error`, `page_exit`, or `page_reload`.
- CSV uses quoted fields, doubled quotes, CRLF record separators and UTF-8. Embedded newlines remain inside quoted fields. Arrays are JSON-encoded once. Missing optional values are empty strings. Booleans serialize as `true`/`false`.

The anonymous UUID comes from `crypto.randomUUID()`. No identifying inputs or analytics are collected. The application never uploads behavioral data.

## Failures and recovery

CSV automatically downloads as `<story-id>_<participant_id>.csv`; Download CSV generates another link to the retained finalized Blob. Session JSON includes story identity, manifest hash, versions, seed (for Zork), timestamps, category/inventory page visits, initial output, termination reason and any error or pending attempt.

An interpreter timeout/failure does not imply that the command completed. The pending click, menu, command, RT and pre-state are retained in JSON as an **unconfirmed** attempt and are not fabricated into a CSV decision row. This distinction also applies to page exit during processing. A failure before any confirmed command produces a header-only CSV; its reason is in JSON.

Recovery writes occur at Start, on category visits, Back/Escape and inventory page visits, before a command and after its response, and at finalization. Storage keys use `exploration-task:v2:<story-id>:` to separate stories. The Zork store also reads earlier `zork-experiment:v1:` sessions as a fallback. A per-tab marker identifies the unfinished session, and local storage retains sessions by UUID plus a latest-archive pointer. Page exit finalizes when the browser delivers `pagehide`; after a crash without that event, recovery marks the saved active session `page_reload`. The new page always creates a new UUID and fresh story. An active timer lost on page exit without a click does not produce a row.

Storage is best effort, with visible notification if unavailable. Browser eviction, private browsing, clearing site storage, quota exhaustion, or abrupt process termination can prevent recovery. Confirmed in-memory results can still be downloaded while the page is open. Local recovery is not a remote backup.

## Procedure version

Version 2.0.0 replaces the flat menu with Move / Action / Bag, removes counted Inventory commands, and displays the live score. Reaction time now includes category browsing. Retain the implementation and action-policy versions when comparing conditions; v1 and v2 are different procedures.

Implementation 2.1.0 adds a scrollable transcript of the opening narrative and all confirmed action/response pairs, including the final response. History reading and the “Latest response” control use no decisions and do not reset RT. The timer includes time spent rereading past turns. This is an additional change in participant information access relative to 2.0.0.

Implementation 2.2.0 keeps inventory visible beside the story, places commands below it, and shows the score in the story header. Starting the session compacts the welcome header and fits the interface to the viewport. Action and inventory pagination use no decisions and do not reset RT. Page visits are recorded in `ui_events` as `<category>:page:<number>` or `inventory:page:<number>`; the full available-action array remains in each decision row. Automatic refitting on resize is not a menu visit. The persistent inventory and viewport-dependent pagination change information access relative to 2.1.0.

Implementation 3.0.0 hides the full welcome header after Start, exposes a maximum of nine main actions together, and places item actions within the bag panel. The cap is applied in the worker before any options reach the UI/controller. Priority filtering does not execute speculative commands, change story memory, or reset the timing model. Bag actions have no count cap and remain available through sidebar pagination when necessary. Both the information shown and the available action space differ from v2; Zork action policy is 3.0.0 and the JSON menu metadata version is text-2.0.0.

Implementation 3.1.0 restores Move / Action / Bag as persistent tabs below the story. Each category independently retains at most nine choices; Bag choices move from the sidebar into the shared grid and no choices paginate. The sidebar continues to show inventory. Move is selected initially; subsequent turns preserve the selected tab. Category visits use no decisions and do not reset RT. The worker applies the same effect priorities independently to each category. Zork action policy is 3.1.0 and JSON menu metadata is text-2.1.0, distinguishing this action space from v3.0.

Implementation 3.2.0 replaces persistent tabs with a category-first menu on every decision. Large Move / Action / Bag buttons open their respective submenus, which include a matching Back card in addition to the nine game-choice slots. Back and Escape are free UI navigation, recorded as `categories`, and preserve the current decision timer. Zork action policy remains 3.1.0 and JSON menu metadata remains text-2.1.0 because the retained game choices are unchanged.

Implementation 3.3.0 introduces a centered welcome and four instruction pages before Start. Game content is hidden during the guide instead of previewed. Start requests native browser fullscreen and begins the session only after that transition settles; unsupported or rejected fullscreen falls back to the browser viewport. Reading instructions and the initial fullscreen wait do not enter reaction times or `ui_events`. The viewport layout and the first-narrative exposure differ from v3.2. Action-policy versions remain unchanged.
